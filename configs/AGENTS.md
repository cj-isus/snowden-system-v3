# Серверные конфигурации

- Это публичные шаблоны/скрипты; значения credentials остаются вне репозитория.
- `README.md` описывает ограничения baseline. `server-combined.json` не является
  полной копией прежнего сервера: нельзя им вслепую заменить production config.
- Изменение server render, транспорта, mux, hopping, TLS или DNS требует проверки
  совместимости клиента/сервера pinned версий, а не только валидного JSON.
- Целевой deploy OFF-09: staging → validate → backup → atomic apply → health →
  rollback. Не считать запись файла с post-check безопасной транзакцией.
- Параметры ssh/scp различаются (`-p`/`-P`). Использовать структурированные argv,
  не печатать развёрнутый config и не подставлять секреты в диагностические логи.
- Сейчас режим офлайн. Даже `verify-server.sh` делает внешние обращения: не
  запускать без соответствующего явного запроса. Локальная проверка синтаксиса
  не требует VPS и не доказывает доступность сервера.
- Не отключать TLS verification, не добавлять direct fallback в protected путь.
  Серверный `route.final=direct` и клиентский `route.final=proxy` — разные роли.
