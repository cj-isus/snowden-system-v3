## Независимая проверка

1. В [публичном extended interface](https://github.com/SagerNet/quic-go/blob/ccd46abedd39c6f8384b1df8daf42008724958f5/congestion/interface.go)
   batch callback принимает monotime.Time; нужны также OnPacketsLost и OnAppLimited.
   У [BrutalSender](https://github.com/SagerNet/sing-quic/blob/d83826c306d7c008cafb3fd6d8ee07cbcfd656ed/hysteria/congestion/brutal.go)
   одноимённый batch method принимает time.Time, двух других методов в прочитанном
   package нет. Public monotime alias ведёт к int64-based type, не time.Time.
2. По [правилам интерфейсов Go](https://go.dev/ref/spec#Implementing_an_interface)
   одно имя метода не заменяет совместимость signatures. Это manual type reasoning;
   актуальная web-spec не является аттестацией компилятора продукта.
3. [SetCongestionControl](https://github.com/SagerNet/quic-go/blob/ccd46abedd39c6f8384b1df8daf42008724958f5/internal/ackhandler/sent_packet_handler.go)
   проверяет extended assertion и выбирает ccAdapterEx либо ccAdapter.
   Для рассмотренного Brutal выбирается базовый adapter.
4. Прочитаны оба adapter source: base не имеет внутреннего batch interface;
   extended пересылает дополнительные методы. ACK/loss-timeout dispatch делает
   batch вызов только при успешном internal extended assertion.
5. У Brutal individual ACK/loss methods — stubs. Начальное ackRate=1; дальнейшие
   записи поля находятся в updateAckRate, вызываемом старым batch method.
   Поэтому reviewed normal callback path не обновляет loss-compensation rate.

Сигнатурная проверка без вызова движка не доказывает native dispatch. Она
устанавливает несовместимость source method sets при указанных inputs.
Объявления go.mod и прочитанный cache — не resolver execution/binary attestation.

## Достижимость и оппонирование

HY2 client выбирает Brutal только при положительном actualTx и !RxAuto;
в прочитанном server есть отдельное условие positive requested receive rate.
Default/auto/выбранный канал, реальные значения и текущий VPS здесь неизвестны.
Факт наличия класса не делает его активным для всех подключений.

Отсутствие batch компенсации не отключает общую QUIC loss recovery, retransmission,
SRTT provider или базовый pacing. Cwnd всё ещё зависит от RTT; нельзя назвать
все параметры постоянными или весь transport неработоспособным. Прямой внешний
вызов старого batch method не является доказательством engine dispatch.

Один rename eventTime недостаточен: остаются полный interface и выбор monotonic
sample-window semantics вместо calendar Unix(). Восстановление loss compensation
может увеличить offered load и ухудшить общую очередь/CPU/interactive traffic.
Ни процент выигрыша, ни обязательное включение Brutal отсюда не следуют.
