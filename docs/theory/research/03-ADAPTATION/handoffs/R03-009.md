| Поле | Значение |
|---|---|
| ID / вопрос | **R03-17**: какой механизм не даёт дешёвому ложному успеху самому расширять бюджет исследования, и что без него неидентифицируемо? |
| Короткий вывод | Три слоя: (1) pre-work append-only ledger попыток с фиксированным allowance W и error-целью до наблюдения исходов; (2) per-claim anytime-границы валидны при optional stopping, но репортируемый набор требует union-поправки ≤ 1-(1-α)^W; (3) без ledger доля ложных успехов среди reported неидентифицируема — регистрация есть предположение идентификации, не статистика |
| Статус | **READY_FOR_REVIEW**; дата среза 26.10.2026 |
| Evidence | Логическая модель + первоисточники последовательного анализа (Ширяев1976, Вальд1960-рус., Воронцов2004/2010) + adaptive data analysis (Dwork et al.2015); ручной контрпример ветвящегося бюджета. Никакого исполнения/симуляции |
| Область / дата | 26 октября2026; примыкает к R03-12…16 без их принятия; producer-facing контракт, платформы — read-only потребители |
| Предпосылки | Per-claim anytime-границы уже установлены (R03-15); зависимости кандидатов неизвестны → union worst case; фактическое поле α не измерено |
| Сильная альтернатива | «Anytime-valid CI спасает при любых адаптивных решениях» — ложно: optional stopping ≠ adaptive selection/reporting; контрпример: +1 попытка за успех даёт неограниченный дрейф ложных успехов при α>0 |
| Ready reuse | confseq/Howard pins из §10 как per-claim слой; River не расширяется; ledger — новый минимальный контракт register/record/bound/remaining, владелец producer |
| Reject / цена | Не выводить «эффективное W» ad hoc без модели связности (Воронцов: связность — измеримая структура, не угадывание); не считать ledger защитой от corruption/delay (слой R03-15); safety/admission остаются у платформ |
| Следствие для системы | ADP advisor получает доказательную основу «зачем фиксировать попытки заранее»; адресат — seam006/observations, не замена platform admission |
