Новый результат после 004:

- **R02-11:** separate property coverage: donor certificate D, authorized entry E,
  inner proxy X и destination T. SS2022 и verified inner TLS покрывают разные
  identity/PFS/camouflage задачи. SS type допускает method=none; нужны method/key
  условия. Actual core SS client library2 и server library — разные pinned modules.
- **R02-12:** response request-salt binding и per-Service cache не являются
  глобальным replay/exactly-once. Два caches с общим key — условный manual witness;
  прохождение outer authorization явно требуется. Donor TLS1.3 не даёт SS PFS.

Reuse/adapt: existing GPL-3.0-or-later SS2022 AES-GCM + ShadowTLS либо verified
inner TLS + VLESS, с server/profile/admission/network миграцией. Inner ClientHello
остаётся visible в нешифрующем ShadowTLS data stage, без доказанной inner ECH.
