# R02-006 — IO variants меняют protocol semantics

26 октября2026 · **READY_FOR_REVIEW**, не ACCEPTED.
[REPORT](../REPORT-006.md) · [SOURCES](../SOURCES-006.md).

**R02-13:** actual ShadowTLS0.2.1 ordinary/buffer writer отправляет HMAC до
добавления tag в running state, vectorised writer — после. Receiver ожидает первый
вариант. Symbolic source trace, не crypto-executed reproduction. Buffer/vector
variants также не повторяют scalar cap16384: возможны oversized TLS-looking
records и16-bit length wrap при соответствующих inputs.

**R02-14:** multi-chunk Write не выходит на первой ошибке; если поздний chunk
успешен, может вернуть полный n,nil. Условный ручной IO witness, не live failure.

Контргипотеза проверена: SS server vectorized codec собирает ciphertext и вызывает
lower Write, поэтому обязательная достижимость ShadowTLS vector branch через SS
**отклонена**. Plain no-flow VLESS после lazy header может unwrap к ShadowTLS;
sing copy loop имеет условный batch switch, но runtime source reader/TUN/flags
не проверены. Это source caller path, не утверждение «обрыв после512KB».

Reuse/adapt existing encoder/IO seams с единой recurrence/bounds/errors;
batch syscalls могут содержать несколько valid records. Framing цена9 bytes на
record; no throughput estimate. No integrity-off/direct fallback. Не называть
внутренний framing failure доказанным DPI и не исправлять его одним score штрафом.

Windows actual input snapshots; Android current graph ShadowTLS отвергает,
native path не появился. Future cases **NOT_RUN**. Exact current ST file matched
raw004; sing full tag SHA/Go1.26 raw недоступны, version+module hash и interface docs
помечены с ограничениями. Никаких product changes/tests/crypto/native/live.
