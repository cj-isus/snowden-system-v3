# R02-012 — паспорт решётки доменов отказа на барьере IP/ASN/allowlist

| Поле | Значение |
|---|---|
| ID / вопрос | **R02-22**: какие кандидаты реально выживают при возведённом барьере IP/подсеть/ASN-репутация + allowlist, и какие домены отказа у них общие? |
| Короткий вывод | На барьере {IP-списки + подсетевая репутация + allowlist} нет технически стойкого кандидата: выживают только камуфляж в разрешённую платформу (весь риск — юридический D6) и распределённые системы с ротацией входов. Диверсификация порта обязана идти по разным доменам отказа (TLS/CDN + QUIC/UDP + платформенный), не по числу протоколов; каналы на одном VPS/ASN делят домен |
| Статус | **READY_FOR_REVIEW**; дата среза 26.10.2026 |
| Evidence | Датированные русскоязычные первоисточники (dept.one 2026-04-01; paperpaper 2026-10-13) + Wang et al.2025 + полевой issue; логическая решётка. Никаких измерений со стороны этого исследования |
| Область / дата | РФ, ноябрь2025—октябрь2026; allowlist-эпизоды Москва/71 регион; без обобщения на всю РФ и мобильные сети |
| Предпосылки | Факты — журналистско-аналитические агрегаты (вторичные со ссылками на РБК/Верстку/Медузу); 95/99.5% — заявки сервисов, не независимые измерения |
| Сильная альтернатива | «Больше протоколов = устойчивее» — опровергнуто решёткой: VLESS/REALITY/CDN-VLESS делят D3/D4; выживание требует разных доменов. «QUIC-блокировка убьёт только HY2» — нет, D5 общий со всем UDP-классом (защита и риск одновременно) |
| Ready reuse | Для Snowden: channel-a (VLESS/Reality) и channel-b (HY2) на одном origin-server классе делят D2/D3 — перенос одного канала в иной класс (CDN edge / не-датацентровый egress) — конкретная будущая policy-заявка, не смена кода |
| Reject / цена | Не считать VK-камуфляж устойчивым решением (единоличный владелец домена — платформа); не размещать RU-hosted реле как «резерв» без учёта D6 (реестр РКН, 282-ФЗ) |
| Следствие для системы | Адресат FR-owner: портфель каналов оценивается по покрытию доменов отказа; тесты переключения — по сценариям D2/D3/D4/D5 отдельно |
