# R02-011 — паспорт early-data/replay границы HY2 и ShadowTLS conversion

| Поле | Значение |
|---|---|
| ID / вопрос | **R02-20**: экспонирован ли HY2-auth через TLS 0-RTT в actual caller? **R02-21**: теряется ли VerifyConnection в ShadowTLS default conversion и достигается ли она в composed caller? |
| Короткий вывод | R02-20: в прочитанной композиции без ClientSessionCache найденный путь не даёт TLS 0-RTT; это source-вывод при применимости Go reference, не wire-proof. Добавление кеша само по себе не означает 0-RTT; Initial/replay/admission рассматриваются отдельно. R02-21: lossy conversion реальна (VerifyConnection/ClientSessionCache/ECH не копируются), но v3+utls Snowden-композиция идёт через WithSessionIDGenerator-ветку и её не достигает |
| Статус | **READY_FOR_REVIEW**; дата среза 26.10.2026 |
| Evidence | Source-факты local module cache (go.mod exact pins) + stdlib reference + Snowden render; web primary RFC/blog. Никакого crypto/TLS/QUIC/wire исполнения |
| Область / дата | 26 октября 2026; core1.13.19/b5ebaa1f…, sing-quic v0.6.4-0.20260803…, quic-go v0.59.0-sing-box-mod.4, sing-shadowtls0.2.1, Go1.26.7 reference, render.go актуален на дату среза |
| Предпосылки | Snowden render не меняет TLS-опции HY2 (нет utls/кэша) и shadowtls (utls chrome); production tags with_utls сохраняются; stdlib gate совпадает с прочитанной версией Go |
| Сильная альтернатива | «DialEarly в caller ⇒ 0-RTT включён» — опровергнут stdlib gate (handshake_client.go:358). «ShadowTLS теряет VerifyConnection у Snowden» — опровергнуто ветвлением outbound.go:57-62 |
| Ready reuse | Датированные предпосылки сохранить; перед ускорением отдельно выбрать resumption/0-RTT policy. Общий межсерверный кеш — не обязательный вывод. STD-адаптеру не приписывать перенос VerifyConnection |
| Reject / цена | Цена кеширования/ранних данных зависит от политики билетов, времени жизни и допустимости повтора. Выигрыш RTT не измерен. 3× anti-amplification ограничивает байты, а не весь CPU/RAM; Salamander не даёт общего доказательства защиты от повторов |
| Следствие для системы | Для двух существующих планов: сохранить version/caller ограничения; при реальном допуске 0-RTT установить семантику повторов. Утверждение о единственном replay-store и перенос всех TLS-полей отклонить как необоснованные |
| Что ещё проверить | REPORT-011 §5: отдельно кеш, пригодный билет, resumption и 0-RTT; условный two-instance replay, Initial admission cost и STD VerifyConnection. Все исполнения NOT_RUN |
