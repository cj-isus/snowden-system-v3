# Handoff R02-013 — ECH/SVCB: спецификация, bootstrap и область фильтрации

27 октября 2026. Статус: **READY_FOR_REVIEW**, не ACCEPTED/product/native/live PASS.

## 1. Короткий результат

Прежний номер/месяц стандарта ECH подтверждён: **RFC9849, March2026**,
Proposed Standard. Но правильная система оснований состоит из **RFC9849 +
RFC9848 (ECH DNS bootstrap) + RFC9460 (SVCB/HTTPS)**. Публичный ECHConfig,
GREASE-extension, real-ECH предложение, принятие, origin authentication
и фактическая доступность — разные состояния.

В Windows VLESS+WS/CDN renderer нет включённого real-ECH consumer, хотя
uTLS/chrome fingerprint включает GREASE ECH. Native ECHAccepted существует,
но sing-box common state wrapper его не копирует: false в этой projection
не годится как отрицательное evidence ECH. Это source-границы, не runtime-утечка.

Полный текст FOCI2025 уточняет старую двухпредикатную Cloudflare-сигнатуру:
в описанных измерениях **марта2025, Москва/AS50867** важны ECH-extension,
outer SNI cloudflare-ech.com **и Cloudflare destination-IP range**. 1500 IP —
дополнительные destinations, не ISP/vantage points. Современная общероссийская
rule и механизм на пути владельца этим не установлены.

## 3. Предлагаемое решение

1. Принять **A только как scoped спецификационный crosswalk**, не продуктовый
   promise ECH default/доступности.
2. Рассмотреть **B только как source/caller и observation projection finding**:
   current CDN real-ECH отсутствует в рассматриваемом branch; GREASE и
   ECHAccepted common-state metadata не дают универсального verdict.
3. **C** оформить как датированный внешний measurement-result с одним
   российским vantage scope; старый CF two-predicate пересказ дополнить
   third destination-IP condition и оговоркой fresh-current unknown.

Это предложения, не само-принятие и не независимая рецензия собственного текста.
