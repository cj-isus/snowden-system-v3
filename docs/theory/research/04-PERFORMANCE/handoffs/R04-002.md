## Самостоятельное оппонирование

В REPORT10.9 проверены11 чрезмерных утверждений. Отвергнуты «любой UDP навсегда
блокирует TCP», «RR/queue cap доказывает time fairness», «Go GC/age делают pooled
release безопасным», «DRR/CoDel гарантируют deadline», «reserved Stop lane уже
ограничивает native data path». Базовые claims сужены до exact caller/conditions.

Время выводится только при заданной service curve R[t-T]+ и arrival envelope
sigma+rho*t; тогда delay<=T+sigma/R, backlog<=sigma+rho*T. Эти предпосылки
для текущего Интернета/Go/Android/VPS не доказаны. Packet opportunity bound
не выдается за миллисекундный SLO или гарантию useful application completion.

## Что практически предлагается

1. Платформенным/core owners: после отдельного разрешения конечные scheduler
   и ownership regressions по REPORT10.10 до изменения размера queues/packet cap.
2. Work/bytes/session/retiring conservation с nonfatal overload-drop outcome:
   нынешний handleMessage error закрывает общий carrier и требует осторожности.
3. Рассмотреть narrow MIT quic-go seam для STREAM opportunities и bounded class
   scheduling, существующие x/sync/channel admission и safe cache ownership.
4. Comparative native/loaded-latency/energy/fault приёмка с exact artifact и
   заранее заданными tolerances. Статусы TH/AND/COM/RQ этим не меняются.
