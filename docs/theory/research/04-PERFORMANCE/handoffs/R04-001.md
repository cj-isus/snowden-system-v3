где реальные возможности улучшения и какие shortcuts небезопасны.

## Межтематические вопросы для руководителя

- **R03:** использовать physical cost model и разные cold/warm states;
  выбирать статистику useful completion/missing outcomes по своему контракту.
  Queue admission и local TCP acceptance не считать полезным завершением.
- **R05:** проверить ownership lifetime/lock-order при bounded handler/eviction
  и связь path generation с size budget. Этот пакет не заменяет safety review.
- **R02:** другая fragmentation/packet size меняет wire statistics; меньше
  overhead не означает меньшую обнаруживаемость, нужен отдельный threat context.
- **R06:** различать «ядро запущено», local flow accepted, gate и полезное
  восстановление; не выдавать технические стадии за преждевременный Connected.

## Последовательность разработки, если принята научным руководителем
