## 2. Семантический контракт, который нельзя заменить assertion

| Граница | Current / candidate source | Следствие для remediation |
|---|---|---|
| Normal dispatch | Current R04-10 выбирает base; candidate Brutal full Ex | Narrow backport typed batch + required methods возможен без замены всего engine. Доставка через adapter остаётся отдельным gate |
| Часы | Fixed Brutal берёт seconds из process monotime, не Unix | Сохранять origin/unit/positive domain и определить late-event policy; не считать одно имя monotonic гарантией порядка callbacks |
| Flight before/after | Current injected callback получает post; new quic0.61 документирует и передаёт **prior** только injected, оставляя legacy post | Backport одного нового BBR не меняет current engine semantics. Не вычитать L глобально для всех controllers |
| Packet identity / install | New quic использует per-connection congestion packet number across spaces и firstPacketNumber installation boundary | Type fix не даёт old/current epoch isolation. Старые ACK/loss не должны превращаться в samples нового controller без sent state |
| Retiring packet | New Ex добавляет OnPacketNeutered и notifyLeastUnacked; BBR передаёт их sampler | No-op корректен для Brutal без per-packet map, но не универсальное решение для stateful BBR. Нужен actual terminal ownership |
| PMTU | В прочитанном new0.61 individual call имеет PMTU guard, Ex lost list всё ещё без guard/reason; reports(p) фильтрует installation, не PMTU | v0.7.0 не объявлять закрытием pending R04-12. Typed callback fix может начать учитывать и эти losses |
| Pacer | Candidate seed использует initial datagram size, но refill B×Δ остаётся signed multiply-before-divide с negative-result guard | Не объявлять закрытием всех arithmetic bounds R04-004; контролировать отдельно rate/burst/overflow |

Закреплённые исходники кандидата: [интерфейс][u7-interface],
[обработчик][u7-handler], [Brutal][u7-brutal], [BBR][u7-bbr].
Название исправления не означает приёмку всех ветвей и ресурсов.

Восстановление **Brutal** callback не требует одновременно исправлять semantics
всего BBR: Brutal OnPacketSent использует sentTime/size для pacer и не ведёт
sampler snapshots. Это позволяет меньший первый change scope. Но совместимость
loss/classification, init MTU, API consumers и будущая engine приёмка всё равно
обязательны. Новый OnPacketNeutered нельзя фиктивно stub-ить в stateful controller
лишь ради прохождения type check.

## 3. Модель цены восстановленной компенсации

При корректных nonnegative counters и denominator у рассмотренного алгоритма
α∈[0.8,1], поэтому nominal QUIC-packet pacing P=B/α лежит в[B,1.25B] bytes/s.
Это **не** useful goodput, не full wire rate с IP/UDP/obfs overhead и не physical
service bound. Counter использует packet counts, а не успех каждой useful операции.

Для N активных controllers сумма nominal budgets ≤1.25ΣB_i только при bounded
N и B_i. Нет вывода ΣP_i≤C общего bottleneck. Контрпример модели: два controller
с B_i=0.45C, α_i=0.8 дают 1.125C вместе, хотя baseline budgets суммировались в 0.9C.
C здесь в том же QUIC-byte scope; фактический shared link/CPU capacity неизвестен.
Подтверждённого ускорения/queue latency/energy эффекта нет.

Сильный opposing trace: one-method/full-interface backport начинает принимать
PMTU-sized loss как обычную.49 eligible ACK+1 probe loss в window≥50 дают
α=0.98 и P≈1.0204B без доказанной congestion/полезной payload loss. Числа —
ручная иллюстрация различия eligible outcomes; не observed network. Поэтому
«estimator теперь вызывается» и «поведение подходит общему bottleneck» — два gate.

## 4. Что брать, адаптировать и отложить

| Вариант | Практическая цена / ограничение |
|---|---|
| Narrow backport Brutal Ex/monotime/lifecycle из 4ab2ece | Малый scope существующего controller/callers; GPL obligations сохраняются. Init MTU и current public Ex определить явно. Не переносить BBR/new transport family заодно |
| Coupled core migration к совместимому whole dependency set | Существенно шире: Go/native/JNI/constructor/wrapper/API/profile/build/source closure. Здесь отсутствует доказанная supported core1.13.19 replacement matrix |
| MIT original loss-compensation opt-out / cwnd floor | Reference/adapt policy, другой public interface. Не выдавать за существующий JSON option Snowden или безусловно лучшее поведение |
| Global before-flight subtraction / all-loss filtering / no-op BBR retirement | Reject: исправляет видимость интерфейса, может ломать другие controllers, нормальный congestion response и resource cleanup |

Предложение по порядку: semantic matrix → один narrow compatibility change →
engine receipts → exact artifacts → comparative useful-work/resource cases.
Никаких изменений code/deps/plans/режима/сетевых настроек этим исследованием нет.
