## 2. Какие прежние выводы требуют пересмотра в R04-008/009

1. **20MB → local receive window20MiB**, не глобальная RAM и не DATAGRAM limit.
   RFC9221 §5.3 это исключает; sender credit задаёт peer, не локальная constant.
2. **«PTO ничего не удаляет» неверно end-to-end:** timeout задаёт probes,
   `sendProbePacket → QueueProbePacket → DeclareLost` удаляет history owner.
   BBR sampler retirement и frame retransmission — отдельные holders.
3. **Tracked guards существуют:** SendMode checks40000/50000; count checks не
   доказательство cap underlying capacity/PN holes/sampler/global memory.
4. **«Idle≤30s» не unconditional:** nextIdleTimeout=start+max(negotiated,3PTO),
   start может продвинуть first ack-eliciting send; успешный receive рестартует.
   60s clamp — верхняя граница backoff, не минимальный интервал и не no-spin proof.
5. **Singleflight≠release:** pending slot и connDone освобождаются раньше
   discarded-result/old conn close completion; Window worker Stop/retire —
   существующий сильный guard, который нельзя игнорировать.
6. **«Нет admission» не доказано service.go grep:** accept queue32, raw queue1024,
   callbacks/retry/anti-amplification существуют ниже. Они не дают общего cap
   accepted connections/handshakes. Engine Job не включает memory limit.
7. **CCA-трилемма не theorem.** Paper LINK_ONLY, никаких выводов из него не
   переносилось. Необходим full-text review перед отдельной CCA рекомендацией.

Это адресная correction proposal, не blanket rejection ранних пакетов
и не переименование прежних claims.

Короткий фрагмент — REPORT §9, только предложение. Главный принцип:
