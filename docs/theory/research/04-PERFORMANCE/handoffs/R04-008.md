# R04-008 — паспорт retention-границы sent history при плохой связи

> **Ограничение старого расчёта.** Формулу «20MB∧30s», отсутствие удаления
> по PTO и вывод «singleflight ⇒ одно удерживаемое поколение» ниже нельзя
> использовать как установленный общий предел памяти. В сохранённом исходнике
> ветка отправки PTO вызывает `QueueProbePacket`, а тот — `DeclareLost`;
> тайм-аут также имеет нижнюю границу через 3PTO. Копии до очереди, обработчики,
> история контроллера и завершаемые владельцы имеют отдельную стоимость.
> [Позднее возражение с условиями](R04-010.md) не принято автоматически целиком;
> [основной разбор ресурсов](../../../performance/QUIC-ACCOUNTING-AND-LIMITS.md#4-receive-ready-queue-и-sent-history-имеют-разных-владельцев-bytes)
> сохраняет точную область. Ранний текст оставлен для истории аргумента,
> а не как численный норматив или доказанный предел RSS.

| Короткий вывод | Жёсткого капа на контейнер нет; граница составная: stream-байты ≤ peer conn window (20MB, flow control) ∧ время жизни ≤ MaxIdleTimeout 30s ∧ entries ≤ min(window/min_frame, pps×T) + 2·log₂(T/PTO₀) проб; PTO ничего не удаляет, loss-declaration требует ACK большего PN; single-flight offer ⇒ ≤1 live-поколение на Client |

| Предпосылки | Flow-control честно соблюдается стеком; MaxIdleTimeout не переопределён рендером; entries-оценка требует фактических pps/min-frame приложения (в поле не измерены) |
| Сильная альтернатива | «PTO backoff shift переполнится → busy-loop» — опровергнуто клэмпом maxPTODuration=60s; «дыра на высоком PN ⇒ безграничный RAM» — опровергнуто flow-control по байтам; остаётся микрокадровый trickle как worst-case по entries, требующий прикладной предпосылки |
| Ready reuse | Существующие окна/idle/keepalive константы sing-quic достаточны; новый admission не нужен. Оценку entries нельзя строить без pps/min-frame — фиксировать как предпосылку в любом resource-budget требовании |
| Reject / цена | Не добавлять внешний queue cap поверх history (дублирует flow control и ломает retransmission); не считать reslice освобождением памяти (ёмкость массива живёт до реаллокации — измеримо, но не leak) |
| Следствие для системы | FR-budget адресат: RAM-граница HY2-канала = Σ по клиентам от 20MB∧30s-поколений; R04-002/003 receive-путь не пересматривается |
