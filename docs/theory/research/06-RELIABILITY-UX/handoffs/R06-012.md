## Паспорт R06-012-A — Android authority/capture/lockdown

| Поле | Значение |
|---|---|
| Вопрос | Кто меняет capture set/always-on/lockdown exceptions; что делает prepare/revoke; что известно обычному VPN-provider? |
| Вывод | Builder списки задаёт VPN-приложение (API21), не обязательный системный per-app UI. DPM setter singular `setAlwaysOnVpnPackage` (3 args API24; 4 args `Set<String>` API29), требует device/profile owner. Capture set и policy lockdown allowlist не равны; excluded app без exemption не получает direct при lockdown |
| Evidence | API reference + AOSP release/immutable source, actual Snowden source; не device experiment |
| Pin | Android16 frameworks/base `99b01a65cc4c104933788b3143285ab6bae65827`; Settings `0fb38ed81e9b49d5da4be8f50d9d69865c1192e8`; шесть tag↔commit equality captures |
| Exact callers | DPM setter→DevicePolicyManagerService owner/user gate→VpnManager; Vpn.prepare checks always-on/pre-consent; Vpn.setVpnForcedLocked ranges; Settings restrict/support gates |
| Текущий Snowden | min29/target36; manifest `SUPPORTS_ALWAYS_ON=false`; AndroidTunFactory отвергает package split и partial/excluded routes; explicit-consent repository и scoped nullable OsProtectionReader |
| Предпосылки | Источник AOSP16 не OEM и не одинаковый enforcement всех API29–35. Вывод о provider opt-out — VpnService-путь **без** installed PlatformVpnProfile |
| Сильнейшая альтернатива | `prepare()` может вызвать prepareInternal ранее согласованного пакета, но неподготовленный обычно получает Intent и always-on запрещает dethroning; `isAlwaysOnPackageSupported` имеет раннюю PlatformVpnProfile ветку до metadata. Оба counterexamples учтены |
| Разделение профилей | Personal/work — отдельные user contexts; restricted profiles имеют специальное parent-range inheritance, не тождественны work-profile. Shared/SDK sandbox UID — дополнительная scope граница |

| Reuse / цена | Уже существующие consent lineage/reader/manifest capability; AOSP Apache-2.0 reference, system-only DPM getters не переносить в app. Per-app compiler/always-on encrypted recovery — AND-06/AND-03/04, не закрытые |
| Приёмка | REPORT §7 A01–A09, все NOT_RUN; merged manifest/OEM/native enforcement отдельно |

## Паспорт R06-012-B — Windows arbitration и egress

| Поле | Значение |
|---|---|
| Вопрос | Доказывает ли отсутствие LAN-permit запрет LAN/второго VPN, и что значит HardAction/weight? |
| Вывод | Не доказывает: RFC1918/.local уже выбирают direct внутри engine; original app→TUN и engine→physical — разные классификации. Physical exclusion172.16/12 — отдельный case. Другой VPN direct может блокироваться, а transport через TUN имеет иной matching set; совместимость не установлена |
| Evidence | Русские Microsoft Filter Arbitration/ALE/VPNv2 docs плюс precise wf/source mapping; нет ОС-инвентаря или network capture |
| Pin / caller | wf `v0.0.0-20240214030419-6fbb0a674ee6` (compose.go remote↔cache); sing-box1.13.19 direct.DialContext; Snowden routeRulesWithSplit/WFP specs; AppID from filename, default worker os.Executable |
| Арбитраж | Filter/sub-layer weights раздельны, soft permit может получить block/veto ниже, разрешение layer не разрешает другие layers. Max65535 не доказательство монопольной authority |
| Обнаруженный gap | `HardAction=false` лишь не ставит CLEAR_ACTION_RIGHT в compose.go. Локальное объяснение «поэтому static catch-all мягкий и позже переклассифицируется» не подтверждено: Microsoft default table static block=hard; ALE не гарантирует оживление любого rejected SYN. Это документально/source-semantic сомнение, **не** established leak/неработающая защита |
| VPNv2 область | Native/UWP/profile CSP — не автоматически Wails/sing-box TUN. AlwaysOn=trigger; ForceTunnel=routes; DisableDisconnectButton=UI; LockDown=отдельный профильный enforcement (built-in только IKEv2). ByPassForLocal явно unsupported, XSD наличие не runtime support |
| Сильнейший counterexample | Own AppID permit совпадает, чужой callout veto/другой layer всё равно запрещает. И наоборот, app→192.168 через TUN→engine candidate опровергает blanket LAN-ban без снятия WFP; ответ принтера/SMB/multicast NOT_RUN |
| Reuse / цена | Existing route/flow identity data и guard owner; wf BSD-3 license проверен. Не добавлять callout driver, не изменять hardness/route exceptions ради desk research |
| Приёмка | REPORT §7 W01–W07, все NOT_RUN; native policy semantics и actual combined filters — владелец Windows |

## Паспорт R06-012-C — bounded observability/action

| Поле | Значение |
|---|---|
| Вопрос | Какие observations позволяют сказать «ограничение MDM/защиты», не выдавая права настройки/иконку за защищённый путь? |
| Вывод | Различать authority, API/provider capability, configured policy, applied capture, protected completion. Ordinary VpnService reader не раскрывает чужой allowlist или другие profiles; own WFP shape не final action/egress. При отсутствии scoped evidence источник ограничения остаётся unknown |

| Сильнейшая альтернатива | Timeout при другом VPN icon одинаково совместим с DNS, transport, endpoint и policy failure; нельзя только по ним назначить MDM badge или предложить снятие защиты |

| Цена | Scoped local data/privacy, freshness, foreign-policy uncertainty. Новый telemetry/MDM стек и чтение real user policy не нужны |
| Приёмка | Evidence completeness/unknown/action ownership в тех же finite A/W cases; task-metrics требуют собственного producer contract, ошибочная R03-009 union-формула не используется |
