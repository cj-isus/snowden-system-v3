# R06-003 — что сохраняется при переключении рабочего соединения

Дата: **2026-10-26**. Статус: **READY_FOR_REVIEW**; научный ACCEPTED и продуктовый PASS не присвоены.

## Результат и точная новизна

[REPORT §16…21](../REPORT.md), [SOURCES §5](../SOURCES.md).
COM-09/17 уже запрещают обещать сохранение всех TCP/UDP при обычном switch.
Новое — фактическая цепочка текущего клиента и два более точных контрпримера:

1. Сохранённые старые external flows могут оставаться A при default B; после
   rollback default A не доказано исчезновение flow, успевшего начаться через B.
   Это не автоматически direct leak, но существенно для intent сменить выход.
2. Generic dial может взять A до swap, вернуть conn/register после Interrupt(true).
   Следовательно true сам не drain/cutoff fence. Это ручной conditional trace,
   не выполненный тест/обнаруженная полевая уязвимость всех transport handlers.
3. Outcome разделён `C=(protection,default,old flows,task,observation)`; optional
   quiet intent не отменяет urgent safety/expiry/Stop. Task/remote transaction
   outcome не устанавливается synthetic probe и не должен автоматически повторяться VPN.

## Ready reuse / решения

новый control server/dependency или flow database не требуются. QUIC RFC9000 и
WireGuard roaming — same connection/peer continuity reference, не перенос state
на другой независимый gateway. Mosh — пример application state synchronization,
не VPN drop-in; новый релиз/лицензионная интеграция не выбирались.

protect/bind pinned physical Network и OS underlying reporting различаются;
callback epoch/reporting не доказывает migration, native/device gates остаются.
