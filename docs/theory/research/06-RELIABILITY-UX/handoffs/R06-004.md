Дата: **2026-10-26**. Статус: **READY_FOR_REVIEW** с открытым upstream source gate; ACCEPTED/product PASS отсутствуют.

## Где читать / новое

[REPORT §22…24](../REPORT.md), [SOURCES §6](../SOURCES.md).

Ранее уже запрещали считать ring uptime/полной историей. Новое — actual
Android chain и шесть независимых ограничений: observer coverage, semantic
projection/dedup, retention, state delivery, export selection, evidence authority.
StateFlow conflation не теряет автоматически каждый journal event: latest
snapshot ещё может содержать entries. Увеличение ring/новый logger этого не
превращает в полную causal history.

Условная модель: `K(y)` — истории, совместимые с экспортом y/source/известными
coverage bounds. Категоричная φ требует одинакового истинного исхода во всём K;
контрпример двух compatible histories с разным φ делает её неидентифицируемой.
Ни K solver, ни вероятностная/ML модель/эксперимент не выполнялись.

## Существующее хорошее reuse

limits; validated reply→workerObserved без extra RPC; отдельные obs/recv/record
times; local binding marker не worker restart; text-v2 allowlist/counts/filter;
frozen draft и exact displayed share revision/access TTL. Это уже source,
не предлагается «создать заново». System recipient/native sharing не audited.
Не добавлять OTel collector/SDK/persistent traffic logs только для этой задачи.

Минимальный diagnostic statement: наблюдение→scope/interval→неизвестное→
оставшиеся альтернативы→одно допустимое действие. Raw timeout не диагноз DPI,
пустая история не stopped, times/sequence не доказательство authority/no leak.
