## Угроза, независимость и математика

Mapping/roots должны иметь независимое доверенное основание. Несколько origin,
repo names и key IDs при общем key/custodian не образуют independent domains.
Issuer-side approval не защищает независимо от того же полностью контролируемого
issuer. Honest approver должен содержательно разрешать нужный артефакт/назначение.

Для n independent domains при ≤f compromised нужен t>f; для наличия t approvals
при r недоступных необходимо t≤n−r. Совместимость требует n≥f+r+1. Это собственная
простая модель, не измеренная availability и не доказательство liveness API.
Механизм — threshold authorization, не Byzantine replicated-state consensus:
global latest, одинаковые истории клиентов и instant revocation не следуют.
Clock/as-of и durable progress предыдущих срезов сохраняются.

## Exact guards и недостающая для приложения equivalence

Source уже валидирует repository names перед FS paths, считает уникальные repo
names и отказывает, если несколько разных target groups достигли threshold.
Повтор одного repoName в mapping не добавляет approval. Guards не отсутствуют.

[TargetFiles.Equal](https://github.com/theupdateframework/go-tuf/blob/f5edbde31e5507f46db2069402dc38903fe6d9d4/metadata/metadata.go#L466)
сравнивает Length и Hashes.Equal, **custom metadata не сравнивается**.
Контрпример: одинаковые artifact constraints, разные external custom grants/
security epochs. Выбранный первый target object не доказывает agreement полей
custom. Если критические facts уже внутри exact одобряемого manifest payload,
его digest связывает их; не требовать новые поля только ради новой подсистемы.
Иначе нужна принятая application equivalence/allow policy. Это scope API,
не подтверждённый дефект SDK. Внутренние Hashes.Equal semantics не аудитировались.

## Mapping — отдельная authority

Paths/repositories/threshold/terminating и порядок mappings определяют effective
search policy. Более слабое предыдущее правило или non-terminating fallback
может дать unilateral approval при отказе строгой строки. Наличие threshold2
в одной строке не доказывает required two-party approval protected path.
Adaptive score/доступность не меняют policy.

NewConfig парсит supplied JSON и проверяет supplied roots, но JSON parsing не
аутентифицирует mapping. Для owned immutable config нужны limits/schema,
non-null structures, existing repo references, nonempty URL lists, допустимые
thresholds и unique identities, проверенный порядок/patterns. Полная semantic
validation не доказана просмотренным constructor path; malformed trusted config
не назван exploit. Не подавать inbound map как самостоятельно одобренный anchor.
filepath.Match требует отдельной проверки wire paths Windows/Android.

## IO и availability ограничивают прямое reuse

- Refresh172…182 возвращает первую ошибку при обходе всех clients. Необходимое
  t-of-n условие не означает, что Refresh переживёт отказ unneeded repository.
  GetTargetInfo пропускает per-repo lookup errors — это другой workflow.
- initTUFClients использует repoURL[0] и default updater config: несколько mirror
  URLs в JSON не дают автоматический mirror failover в этом path.
- GetTargetInfo может инициировать refresh/delegated fetch. Cache-disable не
  доказательство complete offline/memory-only closure.
- Shared LocalTargetsDir может конфликтовать; source предупреждает, default
  разделяет targets по repo. Unix mode0700 не доказательство Windows ACL/custody.
- До общей ошибки часть per-repo progress могла сохраниться. Не rollback всех
  roots/floors вместе с artifact; использовать согласованный R05-001/002 protocol.

## Конечные future cases — все NOT_RUN

1. Независимые valid approvals одного exact manifest + все current gates →
   candidate, не installed/adopted.
2. Один repo повторён → не two-repo threshold; aliases одного custodian → не
   independent domains даже при двух counted names.
3. Length/hash group совпадает, custom policy расходится → custom не agreed;
   проверить вариант critical facts inside exact manifest отдельно.
4. Две groups достигли threshold → existing conflict error, не fastest winner.
5. Strict map не достиг threshold, слабый earlier/fallback rule → whole-map
   policy запрещает обход обязательного approval.
6. Unneeded repo offline ломает Refresh, target lookup имеет quorum → различить
   API traces; не synthetic availability PASS.
7. Null/emptyURL/unknown repo/threshold≤0/oversized map → wrapper rejection до IO
   по принятому contract, без предположения обо всех constructor guards.
8. Partial progress→error→crash → допустимый per-scope trust progress сохраняется,
   no reset floors ради повторного согласования.
9. Первый mirror недоступен, второй URL доступен → honest coverage gap этого path.
10. Windows/Android path patterns и shared cache collision → explicit outcomes,
    не приписанная portable/path/native safety.

Strongest counterevidence: алгоритм и substantial guards уже готовы, одиночный
existing pipeline может быть достаточен, exact manifest сокращает доп. state,
common custodian снимает заявленную независимость. Полный malformed-input,
resource/IO/conformance audit не выполнен. Вывод — оценить адресную адаптацию
готового механизма после выбора угрозы, а не писать свою crypto/consensus.
