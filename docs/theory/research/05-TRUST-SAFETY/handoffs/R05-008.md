# R05-008 — паспорт native backup/recovery примитивов

| Поле | Значение |
|---|---|
| ID / вопрос | **R05-18**: что доказывают native backup/recovery-примитивы (DPAPI, Keystore/KeyMint, Backup/D2D, BiometricPrompt) и где restore молча ломает floors? |
| Короткий вывод | Примитивы — слой custody+presence, не authority: authenticity даёт TUF-подпись, freshness — внешний floor-anchor, authority — threshold-политика; restore без внешнего anchor'а откатывает floors. DPAPI-blob невосстановим после смены учётки/password-reset; keystore-ключ неэкспортируем; честная схема — restore только не-key material + fresh consent + подписанная серверная floor-позиция |
| Статус | **READY_FOR_REVIEW**; дата среза 26.10.2026 |
| Evidence | Официальная документация (MS Learn ru-RU схема AD, MS-BKRP, MS Support KB, Win32/Android canonical) + Snowden source dated inputs. Никаких native/SDK вызовов и реальных states |
| Область / дата | 26 октября2026; Windows-потребитель DPAPI (app.go/delivery_state.go), Android EncryptedProfileStore/KeyGenParameterSpec, allowBackup=false; доменные сценарии — только граница |
| Предпосылки | TUF-слой R05-006 и миграционная политика R05-007 остаются владельцами authority; авто-перенос ОС не считается доверенным каналом |
| Сильная альтернатива | «Бэкап vault+blob достаточно для восстановления» — опровергнут трижды: DPAPI-граница учётки, неэкспортируемость ключа, floor-откат при restore |
| Ready reuse | Текущее Snowden поведение уже совместимо (allowBackup=false, DPAPI vault без переноса). Будущий seam: presence-подтверждение критичных операций (BiometricPrompt+CryptoObject / Hello) при включении authentication-required флагов |
| Reject / цена | Не включать backup для trust-состояния без floor-проверки после restore; не считать D2D доверенным переносом ключей; не проектировать «восстановление ключа» — только переустановку с re-wrap |
| Следствие для системы | TH-owner: recovery-план доверия обязан содержать out-of-band recovery secret + серверные подписанные floors; UX-шаг энроллмента — цена, не дефект |
| Что ещё проверить | [R05-008 §5](../R05-008.md): native-вызовы, реальный D2D restore, аудит backup rules всех модулей, реализация out-of-band — NOT_RUN |
