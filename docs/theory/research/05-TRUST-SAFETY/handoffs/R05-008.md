# R05-008 — паспорт native backup/recovery примитивов

| Поле | Значение |
|---|---|
| ID / вопрос | **R05-18**: что доказывают native backup/recovery-примитивы (DPAPI, Keystore/KeyMint, Backup/D2D, BiometricPrompt) и где restore молча ломает floors? |
| Короткий вывод | Custody ключа, аутентификация пользователя, полномочие и непрерывность истории различаются. При откате всех доступных checkpoints без пережившего отказ основания история неразличима. Единственный обязательный серверный floor, биометрия или безусловная потеря DPAPI после любого reset из этого не следуют |
| Статус | Авторский **READY_FOR_REVIEW**, срез 26.10.2026; чрезмерные обязательные требования ограничены в уже имеющемся разборе применения K5, не принятие пакета целиком |
| Evidence | Официальная документация (MS Learn ru-RU схема AD, MS-BKRP, MS Support KB, Win32/Android canonical) + Snowden source dated inputs. Никаких native/SDK вызовов и реальных states |
| Область / дата | 26 октября 2026; Windows-потребитель DPAPI (app.go/delivery_state.go), Android EncryptedProfileStore/KeyGenParameterSpec, allowBackup=false; доменные сценарии — только граница |
| Предпосылки | TUF-слой R05-006 и миграционная политика R05-007 остаются владельцами authority; авто-перенос ОС не считается доверенным каналом |
| Сильная альтернатива | Шифртекст без доступного ключа и откат принятой истории — разные отказы. Нельзя считать безопасным любой backup, но нельзя и объявлять любой restore откатом либо любую смену пароля потерей DPAPI |
| Ready reuse | Существующие store/custody/recovery границы; явно выбранный перенос либо повторное зачисление. allowBackup=false не доказывает запрет D2D на всех OEM; CryptoObject не является подписью показанного смысла. Presence — только при выбранной ручной операции |
| Reject / цена | Отдельно оценить данные, ключ, правила cloud/D2D, surviving history и полномочия. Re-wrap, custodian/OOB/hardware/server имеют разные цены и предпосылки; ни один вариант не выбран автоматически |
| Следствие для системы | Владелец выбирает модель отказа и допустимое основание восстановления. Новый сервер и recovery-secret не обязательны по умолчанию; неподдержанный сценарий должен иметь честную границу |
| Что ещё проверить | [R05-008 §5](../R05-008.md): native-вызовы, реальный D2D restore, аудит backup rules всех модулей, реализация out-of-band — NOT_RUN |
