# R05-003 — provenance не заменяет authority и adoption

Дата среза: **26 октября 2026**. **READY_FOR_REVIEW / NOT ACCEPTED**.

<a id="три-результата-для-решения-руководителя"></a>
## Три результата и условия их применения

1. Уточнить release contract как AND: delivery authority, exact artifact,
   provenance expectations, platform policy, actual adoption. Валидный bundle
   не разрешает rollback/expired TUF target и не доказывает readiness.
2. Для обязательной provenance independently anchor expectations: signer
   issuer/SAN, package/channel, builder/security mode, buildType, source/commit
   и значимые параметры. Начать с threat выбора: issuer-side gate дешевле
   интеграционно, но не является независимой client-side защитой от issuer.
3. sigstore-go v1.3.0 — условный ready reuse/reference, не повод писать свою
   криптографию. Full pin `22d3691c7b8e0c5530fae3c05577690bfef5cd00`, Apache2,
   Go1.25.8. У него уже есть identity/artifact defaults, tlog caps и unique-key
   threshold; не выдавать отвергнутые гипотезы за найденные дефекты.

## Пределы

- Историческое signing time не заменяет current update authority/UTC.
- V1 promise не равно фактическому inclusion; несколько key IDs не доказывают
  независимость операторов/consistency/gossip. Нужна выбранная evidence policy.
- Exact final package identity и native installed/executing image ещё требуют
  отдельного исследования. Существующие Windows source/intent/pair gates
  учтены; SDK не читался, его дефект не заявлен.
- Полная offline dependency closure, revocation/anchor rotation, transitive
  licenses, ABI и overhead неизвестны. Android distribution остаётся future gate.
- Native upstream fetch не удался; web-rendered pinned source пригоден для
  source review, но не выдан за raw Git archive. Local snapshots сняты при
  закрытии и не доказывают absence of drift с начала среза.
