# UI-план v3 (сентябрь 2026): аудит, принципы, изменения

## Найденные дефекты (подтверждено чтением кода)

1. **Мёртвая навигация — критично.** App.vue рендерит `<DashboardView />`,
   `<NetworkView />`, `<SettingsView />` БЕЗ `@navigate`, а внутри этих views
   все переходы сделаны через `$emit('navigate', …)` (объявлено в втором
   `<script>`-блоке). Ни один обработчик не подключён → кнопки «Сменить канал»,
   «Все каналы», «Подробнее об автозащите», «Показать больше», карточка
   «Статистика», «Открыть логи/Тестирование/Настройки», «Открыть раздел NetGuard»,
   «Управление секретами» — не работают вообще. У SettingsView emit даже не
   объявлен.
2. **Задвоение целых разделов на Dashboard** (1835 строк!): «Каналы» таблица
   (есть отдельная страница), «Автозащита» (есть раздел), «О защите» (есть в
   Настройках), «Системная информация» (есть в Настройках). Dashboard должен
   быть сводкой со ссылками, а не копией страниц.
3. **Чужой словарь состояний**: Statistics «Состояние VPN: stopped/running» —
   сырые машинные слова вместо lifecycleLabels; probe-статусы английские.
4. **Заголовок с грамматической ошибкой**: «Отчёт о проверки пути».
5. **Устаревшая подсказка** на Statistics: «Кнопки периодов задают шаг подписей
   оси» — кнопок периодов нет.
6. **Каналы-страница**: сводка статусов не кликается (текстовые чипы вместо
   фильтров), подсказка «Переключение доступно при запущенном VPN» не объясняет,
   что делать при остановленном VPN; при выключенном канале кнопка «Выключен»
   без объяснения почему.
7. **Мёртвый файл** ChannelsView.vue (209 строк) — не импортируется никем.
8. **TUN-режим**: биндинги IsTUNMode/EnableTUN/DisableTUN есть, composable
   готов (setTUNMode), но в UI нет ни одной кнопки переключения режима —
   управлять TUN из интерфейса невозможно.
9. **blockedReason не показывается** на странице Каналов: пользователь видит
   «проверен live» у 3 каналов, но BLOCKED = no_validated_channel объяснить
   нечем (причина живёт только на Dashboard).
10. **Dashboard hero**: дисконнект-кнопка дублирует power-кнопку; egress-IP
    достаётся хрупким регекспом из detail.

## Принципы (не нарушать)

- **Факты**: null = «нет данных», ничего не выдумывать (AGENTS §3.6).
- **Навигация — события, а не чудо**: единственный механизм — provide/inject
  `useNav()` из App.vue; любые `$emit('navigate')` запрещены.
- **Статус = цвет + слово** из labels.ts; сырые машинные слова в UI запрещены.
- **Никаких карт/флагов/выдуманных задержек** (запрет владельца).
- Wails-сборка не должна тянуть мок: dev-мок включается только `?mock=1`.

## Изменения по файлам

| Файл | Что делаем |
|---|---|
| `composables/nav.ts` (новый) | `navTo(id)`, `useNav()`: provide/inject; App.vue — провайдер |
| `App.vue` | provide навигации; слушатели не нужны — provide решает всё |
| `DashboardView.vue` | переработка: убрать задвоенные разделы (Каналы/Автозащита/О защите/Системная инфа), компактнее, все кнопки — через useNav, добавить переключатель SOCKS/TUN, честный blockedReason с расшифровкой, инлайн-шаги probe вместо увода «Результаты проверки» |
| `StatisticsView.vue` | lifecycleLabels, русский probe-отчёт (ProbeReportView), убрать протухшую подсказку |
| `ChannelsPageView.vue` | чипы-фильтры кликабельны; колонка «Действия» объясняет stop-состояния; blockedReason на странице |
| `ChannelsView.vue` | удалить (мёртвый) |
| `NetworkView.vue` | рабочая навигация на NetGuard |
| `SettingsView.vue` | рабочая навигация на Секреты (emit-блок удалить) |
| `mock/backend.ts` (новый) | dev-only: перехват api при `?mock=1` для визуального теста |

Проверка: vue-tsc, npm run build, go test, визуальный прогон всех экранов
в превью с mock, потом wails build.
