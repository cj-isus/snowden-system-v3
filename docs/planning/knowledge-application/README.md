снимки и ограничения новых сведений о VPS/CDN. Они задают следующий порядок работ;
статусы требований остаются в реестрах владельцев. Неполные предложения не считаются
готовой реализацией или проверенным поведением.

[Общий план KA-1](PLAN.md) сохраняется как основание минимальных контрактов и
межплатформенной последовательности. Ниже — аналитические срезы 28–29 октября: обоснования и источники
решений. Описания «текущего кода» в них относятся к названному source-срезу;
новые изменения проверяются по плану платформы и реестру владельца.
Новые исследования остановлены.

## Что должна дать сводка

Для каждого знания: источник и предпосылки → существующая реализация/пункт плана → обоснованное решение → конкретное изменение → владелец/зависимость → будущая приёмка. Уже написанный код не считается runtime проверенным; идея может быть отложена или отвергнута.

## Правила применения плана

1. Все уникальные знания, в том числе архивные и поздние, имеют понятное disposition. Пропуски/спорные claims видны.
2. Предложения сверены с actual source и existing plan IDs; изменения текущего дерева после source cut учтены.
3. Сначала safety/lifecycle/trust и честный UX, затем bounded performance/адаптация, затем дополнительные transports/features с доказанной пользой.
4. Задачи разделены по реальным module owners; минимум frozen interfaces, независимые ветки ПК и Android, единая интеграция руководителем. Новые зависимые чаты не создаются.
5. Эксплуатация рассчитана на один купленный VPS с явным single point of failure. БД/control-plane/кластер не вводятся без demonstrated need. Сейчас SSH/deploy не разрешены.
6. Задачи передаются только соответствующим существующим владельцам с конкретными входами и выходами этапа. Нативные/устройственные/полевые проверки остаются отдельными gates.
